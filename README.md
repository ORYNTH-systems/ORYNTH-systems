  <strong>Constitutional execution-governance and runtime-integrity architecture for adaptive, autonomous, distributed, and consequential systems.</strong>
</div>

<br>

ORYNTH develops architectures for systems whose technical capabilities may exceed the authority they should independently possess. It separates capability, authority, admissibility, continuity, execution, effect, evidence, reconciliation, and finality so that consequential actions remain bounded, reviewable, and verifiable.

> **Capability does not establish authority.**

A system may be technically capable of producing an action without possessing the valid authority, present eligibility, continuity, or evidentiary basis required to execute it.

## The governing distinctions

| ORYNTH preserves | Meaning |
|---|---|
| Capability is not authority | Technical capacity cannot authorize itself |
| Authority is not admissibility | A valid authority source does not make every action eligible |
| Authorization is not continuity | Earlier permission may become invalid as state changes |
| Evidence is not authority | Evidence supports evaluation but cannot authorize action |
| Eligibility is not execution admission | Passing one stage does not bypass the execution boundary |
| Execution is not verified effect | Attempted execution does not prove the intended result occurred |
| Effect is not resolution | A produced effect does not establish complete resolution |
| Resolution is not reconciliation | Closure requires state, evidence, and consequence to align |
| Reconstruction is not execution | Rebuilt state must not reproduce external effects |
| Replay is not authority | Replayed evidence cannot create a new authorization right |

## Public-status boundary

The public ORYNTH profile contains research architectures, formal specifications, reference implementations, proof corpora, assessment systems, developing surfaces, and domain applications. These artifact types are related but are not interchangeable.

Public evidence demonstrates behavior only within its declared architecture, version, assumptions, corpus, implementation, and test environment. It does not independently establish universal correctness, production readiness, production security, legal compliance, certification, accreditation, governmental approval, or the absence of undiscovered defects.
